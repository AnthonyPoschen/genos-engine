Lavapipe, 640×360, High, Anthony's pose (eye 14.5, 1.7, 23.5, yaw −0.3554, pitch 0.08), day fraction 0.12, boxes still, other lamps still, sun frozen, dynamic 0. The binary is `cursor/bounded-quarters-115f` at `96588f01`, built from that branch and not merged here. The path reference is `img/hall-path-reference.png` (72 spp). ## Lamp 3, 1M mid-move difference (cause not established)

Lamp 3 moves from (12.5, 2.6, 21.5) to (14.0, 2.6, 22.5) over 40 frames. The red box is the albedo region in front of the camera (7,756 pixels, all nearer than 6 m). "20 codes" is 8-bit Rec.709 luma of the saved picture. Apart counts either side. The heat map is `img/f0-lamp-mid-redbox.png` (red = the red box, 20 codes or more off the flag-off frame).

| | Red box ≥ 20 apart | Red box mean abs | Direct, red box ≥ 20 |
|---|---|---|---|
| Mid-move (engine 190 vs 192) | 5.56% (431 / 7,756) | 7.17 | 0.05% (4 pixels), mean abs 0.53 |
| Lamp just stopped (209 vs 211) | 4.18% | 6.53 | |
| Held (both frame 331) | 0% | 2.56 | |

Direct matches. The difference is in the stored texel, not the per-pixel direct term. After the hold the two pictures agree by the 0% at 20 codes, which is what the 4070 run did.

The red-box shares above are one run each, and the two pictures of a pair are one engine frame apart in lamp position (move_start 168 on, 169 off). Treat them as the size of the effect to within a factor of two (see the review rerun below), not as a gate value.

Over the 40 move frames, `lightingsc`:

| | Rays peak | Rays mean | `partial` | `sets` | `extra` |
|---|---|---|---|---|---|
| Flag off | 1,404,928 | 712,804 | 2 | 237,686 | 332,929 |
| 1M | 1,000,048 | 768,378 | 529,188 | 160,756 | 135,539 |

1M commits 160,756 / (529,188 + 160,756) = 0.233 of its quarter visits. That is one shown set per four quarters (`partial / sets` = 3.29). It is not a stuck fourth quarter: the sets do land.

One frame of each, from the same window:

- Flag off, frame 179: `partial 0`, `sets 9506`, `extra 9506`, rays 974,096. `extra` counts a visit with `run > 1`. The set is traced and shown in that visit.
- 1M, frame 185: `partial 14225`, `sets 0`, `extra 0`, rays 773,264. Every visit that frame was one quarter, and none of them reached the fourth, so the shown mean did not change. Frame 192 is the same shape (14,243 partial, 0 sets) at 775,968 rays.

The shader forces one quarter per visit on this path. `lighting_cache.comp` adds the quarter into the partial sum and returns without writing the shown mean while `q < LIGHTING_SC_QUARTERS`. The mean is written on the fourth quarter, and `lighting_lamp_noted()` then sets the blend `k` to 1, so that set replaces the old mean. With the flag on, a fine texel whose lamp ring has actually moved (`lighting_lamp_ring_moved`) takes the settle young list with `ms = 1`, not `lighting_bounded_bucket`. Flag off takes the remaining quarters in one visit.

**Hypothesis, not a finding.** A texel then shows its previous mean for several frames and a mean averaged across the frames its quarters were traced, which would be the softer highlight. What the measurements show is that commits come in waves (the per-frame `partial` / `sets` rows in `fill-curve-f0.json`: about 14,200 partial and about 0 sets for four frames, then about 9,000 sets for four frames), so a texel's set takes about eight frames to commit, not three or four. That is consistent with the hypothesis. It does not show that the commit delay is what makes the red box differ, because the same ratio (`partial / sets` about 3) holds in the still fill before the lamp moves (681,495 / 226,996).

**Review rerun, 11 Nov, same binary (`96588f01`), same script, lavapipe.** Flag off against 1M, red box, same pairs:

| | Mid-move apart ≥ 20 | Mid-move mean abs | Just stopped apart ≥ 20 | Held mean abs |
|---|---|---|---|---|
| Doc run | 5.56% | 7.17 | 4.18% | 2.56 |
| Rerun | 2.27% | 6.75 | 0.15% | 1.65 |

The size of the 20-code difference moves by more than two times between runs. In the rerun the 1M picture is not darker (mean code delta -1.68, so brighter; 0.06% of pixels darker by 20). "Softer and darker" is not a stable description. The held picture differs by 1.65 to 2.56 codes between two processes, which is the noise floor of this comparison.

**Ablation, one try.** In a scratch worktree of the #265 branch the young list took a whole set (not one quarter) for a texel whose lamp ring moved. That is the change the hypothesis says would close the gap. Rays and commits moved as the hypothesis predicts (`partial` 529,158 to 332,739, `sets` 160,930 to 283,808 over the move), and the red box did not get closer to flag off: 10.1% apart at mid-move, 9.9% just stopped, and a held mean abs of 5.75 (it also changed the settled picture). One crude change, one run, so this does not rule the hypothesis out. It does mean the cause is open, and F1 must measure it (the age of the shown mean per texel against the lamp move frame, with several runs per arm) before its reference copies this rule.

## Not changed

Showing a partial quarter, or blending the unfinished set, would be a different picture from the one #265 stores. Nothing in #265 was patched. The fourth quarter does land, and the hold frame matches.

## What F1 should change

F1 is the CPU reference (tile pick, water-fill, deposit, resolve, share). It should model #265's quarter rule as it is (a mean is published after four quarters, and a lamp note replaces it with that finished set), and it should measure the per-texel age of the shown mean against the lamp move before it claims that rule explains the lag. F1 does not patch #265. If the 1% lamp-lag gate cannot be met under a 1M ceiling, the design's next stage is F5 (path vertices), and #265 stays the fallback.

## Not in this change

The stage table also names a first-hit distance histogram and a ray-efficiency counter. Neither exists in the current `lightingsc` words, and both need a new shader counter. They are not added here.

## Networking

- Replicated state: none. The fill curve and the knockout are a local picture measurement.
- Authority: the client that shades the cache.
- Prediction / rollback: none.
- Determinism: the pictures are not a cross-device replay. Lavapipe and the 4070 are compared as numbers, not as matching pixels.
- Headless server: a server does not run this cache.
