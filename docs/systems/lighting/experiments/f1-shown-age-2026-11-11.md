# F1: age of the shown mean during lamp 3's move

Lavapipe, 640×360, High, Anthony's pose, sun frozen, boxes and lamps still except lamp 3. Lamp 3 moves from (12.5, 2.6, 21.5) to (14.0, 2.6, 22.5) over 40 frames. The move starts at engine frame 168–170, after the still fill. Three runs with the flag off (this branch) and three with #265 `bounded_quarters` at 1,000,000 (`96588f01`, not merged). `GENOS_LIGHTING_SC_TRACE=1` stamps the frame of each shown-mean commit and tallies the near red box. The tally is off when that variable is unset, so a shipping frame does not write the stamp.

The red box is 7,756 pixels (albedo r>0.45, g<0.35, b<0.35, distance < 6 m). 6,922 of them have no live cache slot. 834 have one. That split is the same on both binaries at every mark below. The age is of those 834.

**Review correction (11 Nov).** The 6,922 are not a coverage gap. Every one is on a turned surface (`slanted`, flag 2048): the box is yawed, so those pixels have no 12.5 cm texels by design and compose reads probes there (`lighting_world_irradiance_in` returns zero for a slanted normal). A flag-off lavapipe run prints `never 6922 noslot 6922 slanted 6922` from frame 8 to the end, so the tally's texel lookup cannot see them and the split never moves. The age table therefore describes only the 834 axis-aligned pixels (11%). The 7.9–10.7 code darkness below is scored on all 7,756, mostly on the pixels the age does not cover. The table shows the fine-texel commit is not stale for the 834. It does not show that a quarter hold is not the lag cause for the 6,922; that needs the age (or the shown value) read on the probe path. A commit on the stamp's own frame counts as postdating it.

By the short hold, every 1M commit postdates the stamp. Flag off still has 12–19% predating, and the mean age is still 19–28 frames.

## What that says about the lag

The 1M shown means are younger than flag off, not older. A quarter hold (commit only on the fourth 16-ray quarter) would leave 1M older than a path that publishes every visit. The opposite happened. The CPU reference therefore publishes a deposit in the step it finishes (`CommitRule::Immediate`). `HoldQuarters` remains in the checker as the comparison the measurement did not select.

The red-box picture does differ. Mean absolute luma codes, flag off against 1M (negative signed delta means 1M is darker):

| pair | mid abs (signed) | stop abs (signed) | after abs (signed) |
|---|---:|---:|---:|
| off 1 vs on 1 | 10.04 (−7.88) | 7.74 (−5.69) | 5.50 (+3.04) |
| off 2 vs on 2 | 9.85 (−9.84) | 7.91 (−7.87) | 3.10 (+0.14) |
| off 3 vs on 3 | 10.72 (−10.72) | 9.36 (−9.35) | 7.83 (+5.97) |

Flag-off against itself is 0.12–0.24 codes at the same marks, under the 1.65–2.56 floor from the F0 rerun. 1M against itself is 5.1–6.4 codes at mid, so that mode is noisy, and the signed gap of about 8–11 codes is larger than that noise and has the same sign on all three pairs: 1M is darker while its commit is 2–3 frames old.

The lag is not stale shown means, and it is not the flag-off noise floor. The value 1M committed is darker. The commit is recent.
